# Второй этап: рабочее пространство дизайнера

## Что реализовано

- Единая тёплая палитра, общие кнопки, поля, панели, заголовки и состояния. Glass ограничен приветственным блоком кабинета и панелями авторизации: ClipRRect и blur 8; проектные изображения и формы не размываются.
- Вход/регистрация используют прежний Firebase email/password сценарий и новые общие компоненты. Пароль больше не обрезается trim; асинхронные обработчики проверяют mounted. После успешного входа старые экраны авторизации убираются из истории навигации.
- `/mode` теперь открывает кабинет с приветствием, шестью последними реальными проектами и переходом ко всей коллекции. Класс ModeSelectScreen оставлен совместимым с прежними переходами.
- «Мои проекты»: поиск по названию без дополнительных запросов, фильтры по реальным состояниям «Черновик»/«Концепция готова», lazy SliverGrid, превью, дата, открытие, продолжение и подтверждение удаления. Старые работы отображаются с названием, полученным из сохранённых style/mode.
- Мастер из четырёх шагов: помещение → предпочтения → фото → обзор и сохранение. Контроллеры принадлежат всему мастеру, поэтому переключение шагов не сбрасывает введённое. Есть ошибки полей, проверка чисел с точкой/запятой, подтверждение закрытия несохранённой формы, загрузка/замена фото, повтор сохранения после ошибки.
- Проверка фото: JPG/PNG по расширению и содержимому, максимум 10 МиБ и 24 Мп, исправление EXIF orientation, нормализация до 1600 px и 220 КБ JPEG. При необходимости дополнительного сжатия разрешение снижается. Исходный файл на устройстве не изменяется. Для облачной записи сохраняется оптимизированная копия, а не исходный файл полного размера.
- После сохранения открывается проект с параметрами и исходной фотографией; AI Studio получает исходное фото и brief. Редактор получает текущую сохранённую основу и размещённые предметы. Legacy-работа по-прежнему открывается как результат.
- Через AI Studio → результат и редактор → результат передаются ID проекта и владельца. Сохранение обновляет тот же документ, сохраняет первоначальные параметры и фото и устанавливает status=ready. Предыдущие версии результата на этом этапе не хранятся.
- На AI/редакторе/результате есть переход в кабинет; профиль адаптирован к общей системе, выход сохранился. Основные функциональные инструменты и backend-запросы не переписаны.
- Списки и страница проекта подписываются один раз, корректно показывают loading/error/empty и прекращают показ прежних проектов после смены аккаунта. Адаптер сохранения привязан к владельцу при создании экземпляра.

## Одна система хранения; миграция не требуется

Единственный источник данных остаётся `users/{uid}/savedWorks/{id}`. WorkspaceRepository — тонкий адаптер над SavedWorksService для UI и тестов, не альтернативная база проектов.

У новых документов необязательный `project` map:

```
project: {
  title, roomType, area, interiorStyle,
  palette, materials, wishes,
  budget, currency: "KZT",
  sourceImageBase64,
  status: "draft" | "ready"
}
```

Верхние поля прежней модели сохранены: imagePath, imageBase64, style, mode, dateLabel, prompt, description, userId, placedItems, createdAt. Дополнительный необязательный thumbnailBase64 хранит составное превью ручного результата, чтобы редактирование не накладывало предметы на уже составленное изображение. При обновлении результата добавляется updatedAt, createdAt остаётся прежним. Legacy-документы без project продолжают читаться без перезаписи или backfill.

Мастер генерирует ID один раз. Создание через онлайн-транзакцию читает этот ID и создаёт документ только при его отсутствии. Повтор из той же формы не создаёт второй проект. Транзакция имеет timeout 20 секунд и максимум три попытки; создание офлайн не поддерживается. Сохранение результата также транзакционно и не воссоздаёт удалённый проект. Перед записью выполняется консервативная проверка сериализованного размера документа: максимум 850 000 байт.

Production-конфигурация, опубликованные правила, backend и прежние пользовательские документы не изменялись. Если опубликованные Firestore rules используют строгий whitelist полей, новые project/thumbnailBase64/updatedAt могут быть запрещены: это нужно проверить с тестовым аккаунтом. Изменение таких правил требует отдельного рассмотрения; текущий клиент не обходит ограничения.

## Исправленные ошибки

- Прежний AI-заголовок с обязательным chip переполнял узкий экран: заменён на Wrap.
- Повторное AI-редактирование из результата передавало imagePath, который AI-экран не восстанавливал; теперь передаются загруженные bytes, а ошибка загрузки отображается явно.
- Сохранение из проектного сценария раньше создавало бы отдельную работу: теперь сохраняется в исходный документ по ID.
- Динамические stream перестроения старого списка устранены: поиск и фильтры используют текущий snapshot.
- Добавлены подтверждения удаления и закрытия формы, ошибки чтения и записи.
- Изображение с повреждёнными байтами могло выбросить RangeError внутри декодера; сервис нормализует ошибку в понятную FormatException.
- У навигации на маленькой высоте появился scroll; фон Material обеспечивает видимость selected/hover/ink состояний.

## Проверки и их границы

Автотесты используют MemoryWorkspace только в `test/`; фиктивных проектов в production-коде нет. Эти тесты проверяют UI и контракт сохранения, а не подтверждают успешные запросы к live Firestore.

- `flutter analyze --no-pub`: No issues found.
- `flutter test --no-pub`: 33 теста. Совместимость legacy, сериализация проекта, сохранение исходных данных при обновлении результата, ограничение размера документа, содержимое/сжатие фото; поиск, фильтры, переходы инструментов, подтверждение удаления, ошибка загрузки/retry, смена аккаунта, валидация авторизации, полный мастер с ошибкой и повтором сохранения, подтверждение выхода из мастера.
- Widget-проверки при ширинах 320, 375, 768, 1024, 1440 px: кабинет и список, формы авторизации, первый шаг мастера, AI Studio/редактор/результат в пустом состоянии и с переданной фотографией. Полный мастер дополнительно пройден на 375 px. Мобильное меню проверено при 320×568.
- `flutter build web --release --no-pub`: успешно, результат в `build/web`. SDK сообщает об ожидаемом Cupertino font family без соответствующего asset; сообщение не блокирует сборку и присутствовало на первом этапе.
- Backend не изменён; платные запросы Replicate и записи production не выполнялись.

### Проверить вручную

1. Вход/регистрация, выход и повторный вход реальными тестовыми Firebase-аккаунтами; отсутствие доступа к документам второго пользователя на уровне правил.
2. Создание, перезагрузка браузера, повторное открытие нового проекта и legacy-работы, загрузка фото из системного file picker; запрет записи/офлайн/повтор подключения.
3. Один разрешённый запрос Replicate из проекта → сохранить результат → открыть тот же проект; повторить ручной редактор с добавленными предметами. Убедиться, что количество проектов не увеличилось и исходное фото не изменилось.
4. Chrome/Safari, touch/keyboard, экранная клавиатура, 200% zoom и большой системный текст. Автотесты Flutter не заменяют визуальное ревью реального браузера.
5. Реальные большие коллекции. Сетка лениво строит карточки, но текущий inherited Firestore stream ещё читает всю коллекцию; серверную пагинацию и отдельные thumbnail-объекты следует добавить до большого пилота.
6. На Web `compute` не гарантирует отдельный поток; проверить скорость подготовки 10 МиБ фотографий на слабом устройстве. При необходимости вынести обработку в worker/сервер. На native используется isolate.
7. Пользовательские предметы редактора по-прежнему хранятся локально в SharedPreferences; их синхронизация между устройствами и разделение по аккаунтам остаются задачами из AUDIT.md. Проверить повторное открытие работы со своими предметами отдельно.
8. Проверить Firebase rules на разрешение дополнительных полей. В репозитории правил нет, поэтому их безопасность и совместимость не подтверждены.
